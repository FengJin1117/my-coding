核心原理：保留不同的“结尾”，合并等价的方案

① 为什么要有四列？

只记出现次数不够。结尾是 202 的方案，下一次加 6 就能得分；结尾是 2 的方案则不能。四列保留四种不同的后续机会。

② 为什么同一个格子取 max？

到达同一个 (i, state)，剩余原串相同，结尾的匹配情况也相同。以后能增加的次数相同，所以只需保留当前次数最多的方案。

③ 为什么不用保存整个生成串？

判断下一个字符能否补出 2026，只需知道末尾匹配到 2 / 20 / 202 的哪一步。页面显示生成串是为了帮助理解；原代码只保存次数。

for i in range(n):
    for state in range(4):
        if dp[i][state] == NEG:
            continue
        # 保留：消耗 1 个原字符，输出 s[i]
        new_state, add = trans[state][s[i]]
        dp[i+1][new_state] = max(dp[i+1][new_state], dp[i][state] + add)
        # 替换：消耗 3 个原字符，输出一个 6
        if s[i:i+3] == "202":
            new_state, add = trans[state]['6']
            dp[i+3][new_state] = max(dp[i+3][new_state], dp[i][state] + add)
answer = max(dp[n])

为什么只检查原串的 202？替换只会产生 6，而 202 不含 6；跨越替换位置的子串一定含有 6，所以替换不会制造新的可替换 202。
